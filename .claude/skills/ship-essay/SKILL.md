name: ship-essay
description: Ship a new Janet Knott photo essay end to end, from ~/Desktop/Janet Knott to janetknott.com. Trigger phrases: "Check ~/Desktop/Janet Knott", "Ship it".
---

Run this pipeline without re-deriving it. "Ship it" includes the push.

1. **Source:** `~/Desktop/Janet Knott/` contains `Essay.txt` (the draft) and `IMG_*.jpg` iPhone photos. Leave the Desktop folder untouched. The draft is sometimes a bare paragraph with no title line; write the title yourself in the house pattern ("The <Venue> in <Place>", "Summer at the <Venue>").
2. **Fact-check** proper nouns in the draft (artist names, artwork and exhibition titles) with a web search before publishing. Drafts arrive unedited, so verify every one; a misspelled artwork title ships as fact.
3. **Preview, never full-res:** make previews with `sips -Z 1024 "<src>" --out <scratchpad dir>` and view THOSE to choose narrative order. Do not view the full-resolution originals; a full ship at original resolution costs a ~15MB transcript. Open an original only if a preview is genuinely ambiguous.
4. **Copy + rename** the chosen originals into `essays/<slug>/` as `NN-descriptive-kebab-name.jpg` in narrative order: establishing exterior first (it becomes the homepage card image), interior/detail shots following the text's flow, human moments near the end.
5. **Resize:** longest side 1400px, target under 650KB per file. Use Pillow, not sips: `ImageOps.exif_transpose` to bake rotation, LANCZOS to resize, `save(quality=q, optimize=True)` stepping q down 85 → 75 → 68 → 60 → 54 → 48, always re-opening the ORIGINAL each pass (re-encoding an encoded file compounds artifacts for less size gain). Never upscale: guard on `max(w, h) > 1400` before resizing, since a bare fit-to-1400 will enlarge a smaller photo. Two reasons sips is wrong here: it leaves some files with an unbaked EXIF orientation flag (a portrait shot ships as `stored=1400x1050, orientation=6`, one EXIF-stripping tool away from rendering sideways) and `-g pixelWidth/pixelHeight` reports pre-rotation dims, so its own output looks landscape when it isn't; and at equal file size Pillow holds noticeably more quality (a dense-foliage frame that sips could not get under target at q60 landed at 569KB at q75). Afterwards assert stored dims match display dims and orientation is 1 or absent, and check for GPS EXIF (none so far, but check).
6. **Essay page:** `essays/<slug>/index.html`, copied from the newest existing essay page. the draft text lightly edited for grammar only, voice preserved; `&ldquo;&rdquo;` quotes; descriptive SEO alt text on every figure; NO visible captions (removed sitewide in ce4a874); no em-dashes; keep the Metricool tracking snippet.
7. **Homepage:** prepend a card to `.essay-list` in the root `index.html` (image 01, title, date, 1-2 sentence blurb).
8. **Social CSVs:** add the new essay to the hardcoded POSTS list in `social/make_autolist_csv.py` and regenerate. `social/` stays untracked; do not commit it. Schema notes (changed 2026-07-20):
   - Each entry needs `mention` (the venue's Instagram handle, VERIFIED by web search against their real account; a guessed handle tags a stranger), plus `bodies` and `short_bodies` with one entry per chunk (chunk count = ceil(images/3), balanced slices like 10 -> 3,3,2,2). Every chunk caption must be distinct; the script build-gates verbatim repeats because they cost ~half the reach.
   - Caption voice (2026-07-20): captions are first person and never refer to the photographer in the third person. No narrator sentences ("Janet Knott lingers on the details"), no credit lines ("Photographs by Janet Knott"). The #JanetKnott hashtag stays.
   - Before regenerating after posts have gone out: add the published `(slug, chunk_index)` pairs under their segment in `POSTED` and update that segment's `LAST_PUBLISHED_SLUG`. Both are keyed by segment as of 2026-08-26, because the three autolists run on separate schedules and drift apart (Facebook was a row ahead of Instagram and Threads); the three CSVs no longer share a row set or an ordering. Published chunks are excluded from output so re-imports can't double-post.
   - Don't ask Mark for the published pairs, and don't infer them from the interleave order. Ask for the **remaining queue** of each autolist (a screenshot of each Edit autolist page is ideal), then recover the published set by difference: re-run `interleave` against `POSTS` as it stood at the last import (drop essays added since) to rebuild that generation's row order, and match the queue against its tail. The queue is always a suffix of that order, so everything before it published, per segment. This is exact where the post history is guesswork; the dates stay unknown, so don't invent them in the comments.
   - Tell Mark the Metricool step: delete the autolist's remaining queued items in the UI first (stale captions), then import the three fresh CSVs.
9. **Verify:** static server on :8091 (`.claude/launch.json`, name `janetknott-static`); every image loads, the new card renders, no console errors.
10. **Ship:** one commit on main, `Add "<Essay Title>" essay` (images + essay page + homepage), push to origin. GitHub Pages publishes janetknott.com.
